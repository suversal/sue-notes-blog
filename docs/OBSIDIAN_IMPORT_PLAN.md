# Obsidian 单篇文章导入 V1

## 目标

在写作后台选择一个包含多篇 Markdown 和共享附件目录的 Obsidian 上级目录，再明确选择本次要导入的一篇文章。浏览器只提交所选文章及其实际引用的图片，导入结果为私密草稿。导入不会自动发布，也不会修改 Obsidian 原文件。ZIP 仅作为兼容方式保留。

## 输入约定

```text
ghostty/
├── assets/ 或旧目录 asserts/
│   ├── Pasted image 20260918101852.png
│   └── ...
├── 文章 A.md
├── 文章 B.md
└── 文章 C.md
```

- 默认选择文章所在的上级目录；页面只列出目录第一层的 `.md`，多篇时必须明确选择一篇。
- 兼容方式允许上传 ZIP，ZIP 内必须恰好有一篇 `.md`。
- 图片必须使用普通 Markdown 语法，并指向 Markdown 同级的 `assets/`；兼容已有的 `asserts/`。
- 允许 JPG、PNG、WebP、GIF 和 AVIF，单图最大 10 MB。
- ZIP 最大 50 MB，总解压大小最大 100 MB，最多 128 个条目。
- V1 不支持整个 Vault、多篇批量、`file://`、Obsidian `![[...]]` 或双向同步。

## 处理流程

1. 登录用户选择包含多篇文章和共享附件目录的上级目录；也可以改用 ZIP。
2. 页面列出目录第一层的 Markdown，用户明确选择本次导入的一篇。
3. 浏览器读取所选 Markdown，只提交它实际引用的 `assets/` 或 `asserts/` 图片。
4. 服务端再次校验文件数、路径和大小；ZIP 额外校验加密状态和解压大小。
5. 从 Frontmatter `title`、首个一级标题或文件名推导文章标题。
6. 按真实文件签名识别 MIME，并用 SHA-256 复用已有 Media。
7. 新图片由服务端上传 ImgBed，Markdown 图片转成 Payload Media 关联。
8. Markdown 转为 Lexical，以私密草稿写入文章和第一个修订版本。
9. 成功后进入编辑页，由用户继续预览与发布。

## 验收标准

- 一个目录存在多篇 Markdown 时，只导入用户明确选择的一篇。
- 有图和无图的文章都能生成草稿。
- 空格编码的中文图片路径可正确导入。
- 缺图、非 `assets/` / `asserts/` 路径、超限或加密 ZIP 会显示可操作的错误。
- 同一用户重复导入同一图片时复用已有 Media。
- 导入期间禁用重复提交，错误通过 `role="alert"` 呈现。
- 导入结果始终是私密草稿，不绕过现有预览批准流程。
